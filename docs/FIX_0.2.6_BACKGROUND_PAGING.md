# 0.2.6 返回、后台扫描与分页修复

## 保持不变的照片体验

胶卷继续按可见区域获取快速缩略图；点开 JPG 后自动加载大预览/原图，RAW 保持快速预览。没有自动下载全卡高清图。

## 返回与标题

- 照片预览返回胶卷；导入记录返回胶卷；弹窗先关闭弹窗。
- 胶卷主页首次返回提示“再返回一次回到桌面”，2 秒内再次返回将任务移至后台，不销毁扫描任务。
- 去掉“拾光”“带走的光”标题句号，字重改为 SemiBold、36sp 和略宽字距。

## 后台扫描

- ConnectViewModel 改为由应用级 ViewModelStore 持有，不随 Activity 销毁而结束同一进程内扫描。
- 扫描开始时启动 dataSync 前台服务，显示对象/文件数量和暂停操作；扫描期间持有 CPU/Wi-Fi 锁。完成、暂停、断开或服务停止时释放。
- 扫描服务受保护期间，后台也保留 getstate 保活。进入后台取消可见缩略图预取及未完成的清晰预览，目录扫描继续；回到前台后当前可见缩略图重新请求。
- 服务没有进程被杀后的自动重建扫描功能，也不会在系统强行停止后自动重连。游标仍只在同一协议会话内保留。
- 系统 dataSync 时限回调会暂停扫描并停止服务。Android 15+ 规定后台 dataSync 总时长限制，见 https://developer.android.com/develop/background-work/services/fgs/timeout 。小米省电/锁屏策略仍需真机验证，不能保证系统强行停止后继续。
- 前台服务启动被拒绝时提示保持前台后重试；服务运行时通知权限用于展示进度。首次请允许通知。

## 分页

- 不再把“NumberReturned>0 但没有可下载 res 的对象页”误判为分页停止；按对象数量推进，文件列表仅保留可下载文件。
- 按完整资源 URL 去重，避免不同目录中的 PANA0001.JPG 等同名文件被丢弃；恢复游标同样使用 URL。
- 真正的零进度/页内重复在相同 offset 有界重试 2 次，用较小窗口，不跳过范围；仍失败会保留之前的照片，并记录 offset/请求数/返回对象数/文件数。真正的重复页检测保留，不伪装全卡已完成。
- 默认资源文件上限从 10000 调整到 50000，以容纳 6829 对象中 JPG+RAW 展开的文件数量。
- 以上修复针对可复现的代码缺陷；截图没有原始失败页 SOAP，不能确认哪一种是用户当时的唯一触发点。

## 真机复测

1. 从预览侧边返回应回到胶卷；导入记录返回应回到胶卷。主页连续两次返回才到桌面。
2. 扫描开始后检查通知中的“拾光 · 正在扫描相机”，锁屏 2—5 分钟再打开，对象进度应增加。
3. 扫描期间滚动照片仍快速显示缩略图；只在点开 JPG 后变清晰。
4. 扫描继续越过之前 3700/6829 的位置；检查是否保留不同目录中的同名照片，并最终核对对象进度与相机总数。
5. 通知“暂停扫描”应停止进度并释放后台保护；回到 App 点继续后恢复。断开相机后通知应消失。
6. 快速刷新、暂停再继续、切到导入记录、重新打开 App，核对无重复后台服务、无错误退出。

本机没有可运行的 Android 模拟器或用户相机连接；未完成 UI 运行、锁屏或前台服务真机验证。
