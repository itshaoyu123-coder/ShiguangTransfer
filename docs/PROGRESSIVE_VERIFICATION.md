# 第三版验证记录 — 4.3.11-progressive.3

## 对应真机现象

S5M2 的第二版已能加载并预览照片，但后台读取可能在 150 个对象、298 个文件附近遇到连接中断。旧界面同时显示“读取失败”和“读取提示”，使可用的部分列表看起来像整个连接失败。对象数与资源文件数不同是正常的，不用文件数推进分页下标。

第三版只显示一条扫描状态：有照片而扫描未完成时，提示“后台扫描暂停”，保留预览、选择与下载；后续成功进度清除旧错误。首次读取完全没有结果时仍显示读取失败。顶部单独显示扫描进度和筛选数量。

## 协议修正

- 设备描述与 SOAP/DIDL 统一使用兼容 Android 的 XML 配置；可选特性不支持时继续解析，仍拒绝 DTD 和外部实体。
- 优先使用描述文档中公布的 ContentDirectory 与 ConnectionManager 地址；描述解析失败的文本回退按服务类型匹配。
- Browse 优先发送带引号的 SOAPAction，并保留兼容头部回退；失败日志记录页码、请求数量和响应片段。
- 同一页 HTTP 500 最多退避重试三次；断联/超时最多重试两次。退避期间释放相机访问锁，已加载内容保持可用，预览和下载可以继续。
- 重试耗尽后保留已加载照片；手动刷新仍会重新扫描，不宣称已实现持久化断点续扫。

现有日志未包含 HTTP 500 的 SOAP fault，无法确认其唯一原因。本次完善初始化、兼容性、重试和诊断，不保证所有 HTTP 500 已消除。

## 测试与构建

- 针对性协议测试 27 项通过：分页与恢复 15 项、访问调度 3 项、设备描述解析 6 项、SOAP/DIDL XML 兼容与实体安全 3 项。
- Core 6 项、Transport 6 项通过，其中新增 4 项扫描提示状态测试。合计 39 项，零失败。
- 新增回归覆盖受限 Android XML 工厂、解析器不可用时的服务匹配、带引号 SOAPAction、连续短暂 HTTP 500、设备公布的 ConnectionManager 初始化，以及较早页断联后保留首屏并重试。
- 发布 APK 构建 `:app:assembleRelease --offline` 成功，签名和 manifest 已验证。
- 旧协议全集有 4 项已在未修改上游复现的失败，详见 v1 记录；未声称旧测试全集全部通过。
