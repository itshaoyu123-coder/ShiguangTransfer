# 0.2.0-alpha 分析与改进

输入为用户提供的 `LumaLink-progressive-source-5.zip`，包内实际为 progressive.3。
已先阅读 `PROGRESSIVE_VERIFICATION.md`、`PROGRESSIVE_TEST_GUIDE.md`、设计与执行记录。
以下“原版”指这个上传版本；其历史真机验证声明属于输入文档，不作为本次实测结论。

## 发现与处理

1. 之前的拾光 0.1.x 没有照片预览和 Wi-Fi 配对入口；本次改用上传版本的完整协议与下载链路。
   该链路包括相机公布的 ConnectionManager 初始化、原文件名/缩略图解析、授权刷新和 HTTP 兼容处理。
   没有用户失败时的日志，无法断言旧版下载失败的唯一原因或声称所有 HTTP 500 已解决。
2. 上传版本在 `beforePage` 中检查“是否打开了大图”，导致查看一张已缓存图片也阻塞全部后续扫描。
   改为仅在取图网络请求期间暂让扫描等待，图片显示期间扫描可继续；仍不并发操作相机。
3. 原版全局访问锁和可见缩略图优先策略继续保留。打开大图会取消排队的缩略图，完成后重新请求可见项。
   网格缩略图解码尺寸由 900 降到 420，仍限定 160 张内存缓存。
4. 原版扫描重试耗尽后只有“刷新重读”。本次增加同一协议会话的窗口游标和已加载列表检查点。
   “继续扫描”先核对 Browse 对象总数，再恢复未完成窗口；显式刷新和总数变化均重新扫描。
   对象数从未用 get_content_info 的资源文件数替代。断开或进程退出后不跨会话恢复。
5. `ConnectionManager` 已有 WifiNetworkSpecifier，但以前的拾光入口未提供它。
   本次新增首次 SSID/密码输入、成功连接加密记忆、前台启动时自动请求重连。
   移除网络请求的 INTERNET capability，保持本地相机网络语义，取消过时回调并避免重复握手。
   密码格式在调用 Android Builder 前验证，避免无效输入崩溃。
6. 原版同一文件最终失败/取消会终止整个队列，导致后续任务永远停在 QUEUED。
   改为会话仍存在时继续处理后续任务；实际断线时停止，失败文件仍可单独重试。
7. 下载添加 Content-Range 校验；错误提示保留实际 HTTP/IO 原因，不再统称“连接中断”。
   系统相册写入失败并回退应用目录时记录诊断，不将缓存副本冒充相机原片验证。
8. 授权任务纳入会话取消管理并共享相机锁，移除重复后台授权入口，防止浏览入口与自动授权竞争。

## 界面和操作流程

导入记录提供“打开”入口；应用目录回退文件通过限定路径的 FileProvider 打开。

重新编写 `ShiguangBrowser.kt` 和导航壳，使用暖白与深绿配色。
首页直接是胶卷，连接作为轻量底部表单；没有连接仪表盘或二级文件弹窗。
三列照片网格、轻量选择圈、底部导入操作、大图预览与单张导入、独立导入记录。
显示文件数和对象进度；未知总数保留顺序警告；错误保留已加载照片并提供诊断入口。
新图标、启动背景及通知名称属于拾光；版权与来源放在开源声明中。

## 自动连接边界

首次需要系统 Wi-Fi 权限、Android 连接确认和相机访问确认。
后续 App 提交同一个明确 SSID 的请求，Android 通常复用之前的授权，系统策略仍可能重新询问。
相机热点需要开启；本次没有实现蓝牙唤醒、无交互开启相机 Wi-Fi 或后台常驻自动重连。
手动断开后当次进程不自动抢回网络。自动连接偏好可关闭，记录可清除。
参考官方说明：https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap
