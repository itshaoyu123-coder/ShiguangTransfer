# 0.2.9 胶卷已导入标记

## 行为

- 相机胶卷缩略图左上显示绿色“✓ 已导入”，右上保留当前选择按钮，互不混用。
- 标记来源是本机现有 Room 导入记录，仅 COMPLETED 且有手机保存 URI 的记录参与。
- 资源匹配使用相机完整地址、文件名和记录文件大小，JPG/RAW 分开；不同目录同名照片不互相标记，大小变化时不沿用旧标记。
- 旧版已有的成功导入记录也能参与；没有数据库结构迁移。
- 多次导入同一个资源只显示一个标记；删除部分重复记录后，其他成功记录仍可维持标记。删除最后一条成功记录后标记消失，即使用户选择保留手机文件。
- 手机图库中由其他 App 导入的照片不自动识别；从图库外部删除文件不会即时清除本 App 的历史成功标记。
- 相同地址、同名、同大小但实际内容变化的文件，单靠既有记录无法精确区分；未增加指纹下载或相机查询。

## 性能范围

- 复用已订阅的导入记录数据，不新增 Room 查询、相机 CGI/UPnP/HEAD/GET、磁盘逐图检查或图片下载。
- 本地记录映射和 HashSet 标记索引构建改在 Dispatchers.Default；每个可见缩略图只做集合查询。
- 正式导入流程、文件流、扫描分页、网络锁、缩略图请求和缓存策略没有更改。
- 仍有少量本地集合计算和徽标绘制成本，没有真机对比测速；不能宣称绝对零开销。实现目标是避免增加传输通道工作量。

## 真机复测

1. 覆盖安装后，保留旧成功记录的照片应出现“已导入”；正在导入、失败、已取消的照片不出现。
2. 只导入 JPG，确认 RAW 对应项没有误标；导入 RAW 后各自显示。
3. 新照片成功导入后返回胶卷，确认标记自动更新；进度过程中标记不抢先出现。
4. 删除成功记录（仅记录或记录加手机文件），检查标记更新；若有另一条同资源成功记录，标记仍保留。
5. 同样批次对比导入速度；诊断不应因为徽标多出相机请求。扫描、锁屏、日期筛选、分页动画回归。

本机未连接手机和相机，未完成徽标布局与实际速度真机验证。Lab 直达编辑仍沿用 0.2.8 的待适配状态。
